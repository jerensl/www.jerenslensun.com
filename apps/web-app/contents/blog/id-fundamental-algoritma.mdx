Bayangkan ketika kita membandingkan seberapa cepat seorang pembalap pada berbagai jenis kendaraan seperti mobil, motor, dan sebagainya; tentu saja definisi cepat untuk setiap kendaraan akan berbeda, meskipun keduanya sama-sama dikategorikan sebagai kendaraan. Hal ini juga berlaku pada algoritma yang dijalankan pada berbagai sistem operasi dan perangkat keras yang berbeda, yang akan menghasilkan kecepatan yang berbeda. Pertanyaan selanjutnya adalah bagaimana kita mengukur sebuah algoritma dengan berbagai variasi sistem tersebut. Jika kita mengukurnya menggunakan kecepatan waktu nyata, sebuah algoritma akan sangat bergantung pada sistem, lalu apa alternatifnya.

Dalam ilmu komputer, ada banyak cara untuk menyelesaikan suatu masalah dengan berbagai algoritma. Oleh karena itu, kita perlu menggunakan metode untuk membandingkan solusi agar dapat menilai mana yang lebih optimal. Metode tersebut harus memenuhi beberapa kriteria:

-   Independen dari mesin dan konfigurasinya, tempat algoritma dijalankan.
-   Menunjukkan korelasi langsung dengan jumlah input.
-   Dapat membedakan dua algoritma dengan jelas tanpa ambiguitas.

Untuk mengukur efisiensi dan efektivitas sebuah algoritma ada 2 cara yang kita gunakan, yaitu:

1. Time Complexity (Waktu)
2. Space Complexity (Penyimpanan)

Secara umum, kita memprioritaskan waktu dibandingkan penggunaan penyimpanan karena faktor biaya, tetapi dalam beberapa kasus kita juga perlu memaksimalkan keduanya.

## Fungsi Pertumbuhan

![Growth Rate Function](growth-rate.webp)

Pada gambar di atas kita dapat melihat hubungan antara bertambahnya nilai input dan kecepatan sebuah algoritma. Selanjutnya kita akan membahas fungsi pertumbuhan yang akan kita gunakan dan akan menggunakan gambar di atas sebagai referensi.

-   Konstan O(1): Fungsi ini tidak bergantung pada ukuran input dan selalu memiliki jumlah operasi yang konstan. Contoh: mengakses elemen pertama dari sebuah array atau mengakses nilai dari hash table.
-   O(log n) logaritma: Fungsi ini tumbuh secara logaritmik seiring bertambahnya n. Artinya, fungsi ini akan tumbuh lebih lambat daripada fungsi linear. Contoh: melakukan pencarian biner pada array terurut.
-   Linear O(n): Fungsi ini tumbuh secara linear seiring bertambahnya n. Artinya, fungsi ini akan tumbuh sebanding dengan ukuran input. Contoh: melakukan pencarian linear pada sebuah array.
-   Linear dan Logaritmik O(n log n): Fungsi ini merupakan hasil perkalian antara fungsi linear dan fungsi logaritmik. Fungsi ini akan tumbuh lebih cepat daripada fungsi linear tetapi lebih lambat daripada fungsi kuadratik. Contoh: pengurutan menggunakan metode merge sort atau quick sort.
-   Kuadratik O(n^2): Fungsi ini tumbuh secara kuadratik seiring bertambahnya n. Artinya, fungsi ini akan tumbuh sangat cepat dan menjadi tidak efisien untuk input yang besar. Contoh: pengurutan menggunakan metode bubble sort atau selection sort.
-   O(2^n): Fungsi ini merupakan hasil pemangkatan antara konstan 2 dan variabel n. Fungsi ini akan tumbuh sangat cepat dan menjadi tidak praktis untuk input yang besar. Contoh: menghitung semua kemungkinan kombinasi dari sebuah himpunan (subset).
-   Faktorial O(n!): Fungsi ini merupakan hasil faktorial dari variabel n. Fungsi ini akan tumbuh sangat cepat dan menjadi tidak mungkin untuk input yang besar. Contoh: menghitung semua kemungkinan urutan dari sebuah himpunan (permutasi).

## Asymptotic analysis

Asymptotic analysis adalah metode untuk mengukur perilaku sebuah fungsi ketika nilai input n menjadi sangat besar (mendekati tak hingga). Operasi dihitung menggunakan fungsi f(n) di mana n adalah Time Complexity/Space Complexity. Ada 3 tipe batasan.

1. Notasi Big-θ (Big-Theta)
   Sebuah algoritma dapat dikatakan Big-θ atau tight bound ketika bertambah secara asimtotik sama persis dengan fungsi dari running time yang kita gunakan.
   Secara definisi:
   $"T(n)$ is $Θ(f(n))"$ iff $T(n)$ is $O(f(n))$ AND $T(n)$ is $Ω(f(n))$
   Keterangan:

    -   $T(n)$ merepresentasikan waktu nyata ketika kode dijalankan.
    -   iff merupakan singkatan dari if and only if.
    -   n adalah ukuran input.
    -   $f(n)$ adalah fungsi Growth Rate yang digunakan di mana n adalah parameter input.
    -   $Θ(f(n))$ adalah Asymptotic Bounding yang kita gunakan.

2. Notasi Big-O
   Sebuah algoritma dapat dikatakan Big-O atau upper bound ketika pertambahan asimtotiknya lebih besar atau sama dengan fungsi dari running time yang kita gunakan.
   Secara definisi:
   $"T(n)$ is $O(f(n))"$ iff for some constant $c$ and $n_{0}$, $T(n) \leq c \cdot f(n)$ for all $n \geq n_{0}$.

3. Notasi Big-Ω (Big-Omega)
   Sebuah algoritma dapat dikatakan Big-Ω atau lower bound ketika pertambahan asimtotiknya kurang dari atau sama dengan fungsi dari running time yang kita gunakan.
   Secara definisi:
   $"T(n)$ is $Ω(f(n))"$ iff for some constant $c$ and $n_{0}$, $T(n) \geq c \cdot f(n)$ for all $n \geq n_{0}$.

Dalam wawancara kita biasanya akan memberikan estimasi time complexity dan space complexity dalam 3 kasus:

1. Worst case scenario (paling sering ditanya)
2. Best case scenario (jarang)
3. Average case scenario (jarang)

Banyak sekali miskonsepsi yang menyebutkan bahwa batas atas (Big O) merupakan skenario worst case, padahal setiap skenario memiliki batas bawah (Ω) dan batas atas (O). Namun kita dapat menyimpulkannya seperti ini:

1. Batas atas dari worst case merupakan skenario terburuk dari yang paling buruk yang akan terjadi.
2. Batas bawah dari best case merupakan skenario terbaik dari yang paling baik yang akan terjadi.

## Studi Kasus

Selanjutnya kita akan menganalisis algoritma linear search. Algoritma linear search bekerja dengan cara mencari sebuah nilai dengan melakukan iterasi terhadap array; jika nilai tersebut ditemukan maka akan dikembalikan nilai "True", jika tidak ditemukan maka akan dikembalikan nilai "False".

```go showlinenumbers theme=orange
package main

import "fmt"

func linearsearch(nums []int, find int) bool {
	for _, item := range nums {
		if item == find {
			return true
		}
	}
	return false
}

func main() {
    items := []int{95,78,46,58,45,86,99,251,320}
    result := linearsearch(items,58)
    fmt.Println(result)
}
```

Untuk menganalisis time complexity, kita perlu memahami apa yang algoritma tersebut coba lakukan. Kita dapat melihat pada baris ke-6 terdapat iterasi terhadap nilai array `nums`, sedangkan pada baris ke-7 terdapat pengecekan apakah nilai yang diiterasi `item` sama dengan `find`. Saat melakukan iterasi terhadap `nums`, asumsikan nilai yang dicari `find` berada pada indeks pertama array `nums`, maka time complexity-nya adalah Konstan O(1) karena kita tidak perlu melakukan iterasi berulang, sedangkan jika nilai `find` berada pada indeks terakhir, otomatis dengan bertambahnya ukuran array `nums`, waktunya akan bertambah secara Linear Ω(n).

Sedangkan untuk Space complexity, kita perlu melihat apakah selain `nums` ada nilai yang menyimpan nilai lain secara sementara (auxiliary space). Karena tidak ada, kita hanya perlu menghitung ruang yang digunakan oleh `nums`, yaitu Linear O(n), dan nilai `find`, yaitu Konstan O(1). Oleh karena itu space complexity-nya bersifat linear O(n).

Time Complexity:

-   Worst Case: O(n)
-   Average Case: O(n)
-   Best Case: O(1)

Space Complexity: O(n)
