Hai semuanya! Dalam postingan ini, saya akan memandu Anda melalui perjalanan magang saya dengan Servo sebagai bagian dari program Outreachy. Saya akan berbagi apa yang telah kami capai sejauh ini selama periode magang dan pelajaran yang dipetik sepanjang jalan.

## Apa itu Servo?

Sebelum menyelami detailnya, izinkan saya memperkenalkan Servo. Servo adalah prototipe mesin peramban web yang ditulis dalam Rust dan saat ini sedang dalam pengembangan aktif. Pada saat postingan ini dibuat, Servo memiliki [cakupan Web Platform Test 61,8%](https://servo.org/wpt/)

Web Platform Tests (WPT) adalah rangkaian pengujian lintas peramban yang memeriksa seberapa baik peramban mengimplementasikan standar web. Sederhananya, WPT memeriksa berapa banyak [Web API yang didukung peramban](https://html-now.github.io/) dengan benar, memberikan gambaran seberapa lengkap implementasi platform web-nya.

## Pernyataan Masalah

Seperti banyak proyek perangkat lunak berskala besar, Servo menggunakan [GitHub Actions](https://docs.github.com/en/actions) untuk continuous integration (CI) guna memvalidasi pull request. Salah satu langkah kunci dalam pipeline CI adalah linting, yang mengidentifikasi masalah seperti kode yang bertele-tele atau suboptimal, penggunaan API yang usang, penggunaan API yang tidak aman, dan kode yang tidak mengikuti gaya Servo. Tujuan pekerjaan magang saya adalah memperbaiki hal ini dan membuat pengalaman linting lebih membantu bagi kontributor baru maupun berpengalaman.

## Tantangan

Mengadopsi Pyrefly memiliki beberapa tantangan. Ia mengikuti pola desain secara ketat, yang dalam beberapa hal lebih baik daripada type checker lain, tetapi juga memiliki trade-off.

Misalnya, pada Pyrefly Anda tidak diizinkan mengubah nama signature metode dari kelas induk. Ini sesuai desain, menurut dokumen mereka [di sini](https://pyrefly.org/en/docs/error-kinds/#bad-override)

> Gagasan panduan di sini adalah Prinsip Substitusi Liskov, gagasan bahwa subclass dapat menggantikan base class kapan pun tanpa merusak program.

Aturan ini dapat menyebabkan program crash. Anda mungkin berargumen bahwa ini bukan masalah signifikan karena jarang menggunakan argumen kata kunci saat memanggil metode kelas, kebanyakan orang hanya peduli dengan argumen posisional. Perhatikan contoh berikut:

```python showlinenumbers theme=orange
class Base:
    def f(self, a: int) -> None:
        pass

class ArgsWithDifferentName(Base):
    def f(self, _a: int) -> None:
        pass

def uses_f(b: Base) -> None:
    b.f(a=1)

uses_f(ArgsWithDifferentName())
```
