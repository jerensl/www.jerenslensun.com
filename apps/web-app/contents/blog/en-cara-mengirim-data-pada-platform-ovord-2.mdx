The Ovord 2 Platform is an IoT platform that can monitor data sent through embedded devices such as the ESP32, in realtime using data visualization in the form of graphs and tables, that data is stored on the server and can be downloaded using csv file format, so it can be reprocessed for other purposes. This platform also has flexibility towards the sensors used, but for now some sensor types are not yet available.

## Prerequisites:

1. You must have an account first.
2. The account has been verified via email.
3. Having an embedded device such as arduino or esp32.

## Registering a new device

To go to the platform, you can go to the following [link](https://dashboard.cec-unsrat.com/). After logging in, you will be redirected to the dashboard page. To enter the device management page, press the `Device` menu on the navigation menu located on the left. If no device has been registered yet, add one by pressing the `+ Add New Device` button, after that you will be redirected to a modal containing the device form.

You will be asked to fill in the following columns:

-   Device Name: the name for the device you use.
-   Device Short Name: the short name of your device, for identification purposes. That name is unique, applies to all platform users and can only be claimed once.
    In the sensor section you can also add sensors based on your needs by pressing the `+` button located below the sensor, likewise to delete them you can press the `x` button aligned with the sensor to be deleted.
-   Sensor Name: the name of the sensor used, for identification purposes. That name is unique,
    this means that every sensor in one device must have a different name.
-   Sensor Type: the type of sensor to be used.
-   Sensor Unit: the unit of the sensor to be used.

After creating the device, you will get information about the sensor short name along with the token that will be used to identify the device.

## Connected with embedded device.

> For the example below we will use the ESP32 as an example, because ESP32 arduino performs abstraction against esp-idf, some libraries such as for example for https connection may not work, because technically ESP32 is different from arduino, the example below may not work for devices other than ESP32 such as ESP8666 and some arduino products.

To send data on the ESP32 device, an internet connection is needed first, for that we need a library to configure the ESP32 device with the internet network using the wifi embedded in the ESP32, here we use the WifiManager library, as written in its official documentation on [github](https://github.com/tzapu/WiFiManager), this library is able to work on ESP8266 and ESP32 type devices. The way WifiManager works is by preparing a web server that will be used to enter credentials through the Wifi Access Point, and the credentials will be directly stored in the embedded device storage.

Below is a simple coding example that we take from its official documentation on [github](https://github.com/tzapu/WiFiManager),
in the `autoConnect` function there are 2 arguments that we must fill, where:

-   The first argument is the SSID.
-   The second argument is the password of that hotspot.

```arduino showlinenumbers theme=orange
#include "Arduino.h"
#include <WiFiManager.h> // https://github.com/tzapu/WiFiManager

void setup() {
    WiFi.mode(WIFI_STA);
    Serial.begin(115200);
    WiFiManager wm;
    bool res;
    
    res = wm.autoConnect("AutoConnectAP","password");
    if(!res) {
        Serial.println("Failed to connect");
    } else {
        Serial.println("connected...yeey :)");
    }   
}

void loop() {
}
```

After that you can connect using a hotspot through your phone or laptop to the embedded device, to fill in the wifi credentials that will be connected to the embedded device, the way is by entering the browser, then typing the following url http://192.168.4.1/, there you will go to the page to fill in the wifi credentials that will be connected to the embedded device.

Next we will do data serialization into JSON format, here I will use ArduinoJson, to help with serialization. In the ArduinoJson library, there are two ways to store JsonDocument, namely into the stack or into the heap:

-   Use `StaticJsonDocument` to store json data into the stack (recommended for documents smaller than 1kb)
-   Use `DynamicJsonDocument` to store json data into the heap (recommended for documents larger than 1kb)
    You can read more about it here [Arduino JSON](https://arduinojson.org/v6/api/jsondocument/)
    Whereas to create an array you can use `doc.createNestedArray()`, then you can call the `add` method to add a value to that array.

```arduino showlinenumbers theme=orange
#include <ArduinoJson.h>

void setup() {
}

void loop() {
    int arraySize = 2;
    String sensors[arraySize] = {
        "temp-01",
        "temp-02",
        };
    float values[arraySize] = {
        0.4,
        0.1
        };
        
    StaticJsonDocument<1024> doc;
    doc["deviceToken"] = String(token);
    
    JsonArray sensor = doc.createNestedArray("sensors");
    for (int i=0; i< size; i++) sensor.add(sensors[i]);
    
    JsonArray value = doc.createNestedArray("data");
    for (int i=0; i< size; i++) value.add(values[i]);

    String data;
    serializeJson(doc, data);
}
```

After that we need a timer to send data repeatedly based on a certain time interval, here we use millis because millis has a non-blocking feature compared to delay which will block the running of the program.

```arduino showlinenumbers theme=orange
const unsigned long eventInterval = 2000;
unsigned long previousTime = 0;

void loop() {
    
    if (currentTime - previousTime >=  eventInterval) {
	    // coding will be executed based on the specified interval time
        previousTime = currentTime;
    }

}
```

Next we will send data using https, to use https request, here we use the `HTTPClient` and `WiFiClientSecure` library from [espressif](https://github.com/espressif/arduino-esp32/tree/master/libraries).
To send data there is a safe way using a CA Certificate and an unsafe way where there is no CA Certificate, but we will use the safe way.

To send data on the IoT Platform, here we use the https protocol, which requires data such as the following

1. Device Short Name: entered through query parameter or url
2. Token: entered in the body of the JSON to be sent
3. Sensor Name: entered in the body of the JSON to be sent
4. Data: entered in the body of the JSON to be sent

For device short name and token, you can enter them through the global variable `deviceShortName` and `token` whereas
sensor and data you can enter them in the loop function for the `sensors` array and the `data` array,
make sure the order and length of the sensor name is the same as the one in the data and don't forget to change the number of sensors
used in the `arraySize` variable.

void sendData(WiFiClientSecure *client, float values[], String sensors[], int size) {
    HTTPClient https;

        https.addHeader("Content-Length", String(data.length()));
        https.addHeader("Accept-Language", "en-US,en;q=0.9" );
        https.addHeader("Accept-Encoding", "gzip,deflate" );
        https.addHeader("Keep-Alive", "300" );
        https.addHeader("Connection", "keep-alive");

        int httpCode = https.POST(data);
        if (httpCode > 0) {
        Serial.printf("[HTTPS] POST... code: %d\n", httpCode);
        if (httpCode == HTTP_CODE_OK || httpCode == HTTP_CODE_MOVED_PERMANENTLY) {
            String payload = https.getString();
            Serial.println(payload);
        }
        } else {
            Serial.printf("[HTTPS] POST... failed, error: %s\n", https.errorToString(httpCode).c_str());
        }
        https.end();
    } else {
        Serial.printf("[HTTPS] Unable to connect\n");
    }
}
